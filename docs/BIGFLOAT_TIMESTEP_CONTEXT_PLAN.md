# BigFloat timestep context repair

`recommended_dt` must own the precision needed for its logarithmic magnetic and gyro limits. Stored BigFloat inputs can retain much higher precision than the caller's active context. At ambient precision 11, the previous recommendation with stored-precision-256 η=10^200 amplified a production RK4 mode by 1.296709 on both Julia 1.12.7 and 1.13.3. A separate precision-2 scalar helper witness also grows. These are context defects in the recommendation owner, independent of the joint RK4 polygon repair.

The canonical owner is `src/integrators/abstract_integrator.jl`. Validation and type selection remain at the public entry. One internal numeric core holds the existing log-space formula and shared RK4 helper. Native inputs retain their original value-based Real conversion, arithmetic order, native log(NB)/constant dispatch and early CN return. BigFloat, BigInt/Rational{BigInt} parameters and magnetic subcycling with BigInt NB use the same core with timestep-only directed endpoints from `timestep_bounds.jl`. Native CN with only BigInt NB keeps its Float64 result because subcycling is unused there. There is no new dependency, public signature or state migration.

## Bound and context contract

Each private endpoint operation encloses the mathematical result relative to the implemented source constants. BigFloat inputs retain their stored precision; lower and upper conversions use RoundDown and RoundUp. Positive rational conversion in both supported Julia versions rounds the denominator in the opposite direction; negative rationals negate a positive BigInt-rational enclosure, avoiding fixed-width negation overflow. π uses MPFR's directed constant conversion.

Addition/subtraction combine corresponding/opposite endpoints. Products and positive-denominator quotients take extrema over all four endpoint pairs. min/max are monotone componentwise; log, log1p and exp are monotone on their admitted domains. The Hall hypot arguments are nonnegative, making its endpoint rule monotone. abs2 includes zero when its interval crosses zero. Every primitive delegates to MPFR's directed operation; no scalar error constant or arbitrary safety bias is needed. The final lower exp endpoint, converted with explicit caller precision and RoundToZero, cannot increase the enclosed limit.

For K>0 both wave identities are exactly equal:

`K²(sqrt(1+4/K²)+1)/2 = K(sqrt((K/2)²+1)+K/2)`.

Thus the bounded core may select the first identity when the lower log(K) endpoint is nonnegative and the second otherwise, including an interval crossing zero. Interval dependency can widen the bound but cannot invalidate enclosure. The private division owner requires a strictly positive denominator lower endpoint. A NaN, inverted interval, invalid domain or inability to produce a finite positive lower result raises ArgumentError. There is no catch, retry, zero/Inf masking or formula fallback.

Precision and rounding use Julia's BigFloat do-form methods, implemented with task-scoped values in installed Julia 1.12.7 and 1.13.3. Working precision is max(256, largest stored BigFloat precision, caller precision+96). The extra bits size interval width after subtracting C-long-scale logarithms; enclosure, rather than this sizing allowance, proves conservativeness. The returned BigFloat has the caller's precision even when it is 2. Caller precision/rounding and all inputs remain unchanged after success or failure.

This enclosure proof assumes correctly rounded MPFR primitives. The existing [NUM-001 runtime investigation](MPFR_CONCURRENCY_PLAN.md) records concurrent shared-transcendental-cache corruption in stock runtimes; runtime integration remains open. Task-scoped precision/rounding does not repair that native cache. The interleaved-task restoration checks here establish context ownership, not unconditional correctness of concurrent transcendental evaluation. This repair does not close NUM-001 or add a lock, warmup or retry workaround. The root's separate single-process Julia 1.13.3 probe reproduces two incorrect constants; its failed receipt is retained in the runtime investigation. It is separate from the successful timestep package checks.

MPFR exponent range is separate from these scoped settings. It is never changed by the API. Independent precision-256 probes with emin=-3/emax=128 made the old scalar recommendation exceed its full-range value by 0.30016147%. MPFR also forbids arithmetic on retained values outside its active exponent range; Base's fast Float64-to-BigFloat conversion can bypass range checks. The repair admits original BigFloat exponents before public comparisons and checks converted endpoints before arithmetic. mpfr_get_exp explicitly permits that metadata inspection. Narrowed ranges remain accepted when directed arithmetic certifies a finite positive recommendation; other states raise ArgumentError. Exponent-range tests run in their own Julia process and restore limits in finally.

The positive binary64 polygon coefficients differ from their exact decimal values by less than 2^-52. Their induced positive edge-quotient inflation is below 1+2^-50, inside the existing exact 1+2^-20 enlarged-polygon certificate. The independent coefficient receipt checks exact rational values; this repair does not replace that certificate or claim correct rounding of an exact-decimal formula. Magnetic/gyro recommendations still do not certify nonlinear evolution, electron-pressure transport or ion-acoustic accuracy.
